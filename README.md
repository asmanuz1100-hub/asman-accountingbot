- Фактуранинг охирги юкланган версияси ҳисобланади. Бекор қилинган/ҳақиқий бўлмаган/кутилмоқдаги версиялар сотув ёки харидга қўшилмайди.

- Янги «🔎 Топилмаган / хатоли» бўлими: хатолар, тўловсиз фактуралар, фактурасиз тўловлар, барча ёзувлар; саҳифалаш ва PDF экспорт.
- Ҳамкорни қайта боғлаш, реквизит/сана/сумма/йўналишни тузатиш, тўловни аниқ фактурага боғлаш, ҳисобдан чиқариш/қайтариш мумкин. Ҳар бир тузатиш тасдиқланади, фойдаланувчи ID’си ва аввалги қиймат билан тарихга ёзилади. Манба JSON ўзгармайди.
- Акт сверка ва молиявий PDF’лар ASMAN услубида: кирилл шрифтлари, жадвал сарлавҳалари, саҳифа рақамлари, тақсимот усули, диаграммалар ва хатолар рўйхати.

- Фақат ALLOWED_USER_IDS рўйхатидаги фойдаланувчиларга кириш берилган. Бўш рўйхатда кириш ёпиқ.
- Эски ҳужжат тугмаси янги ҳужжатни тасдиқлай олмайди.
- Омборда kg/ton/g бирликлари конвертация қилинади; аввалги бирлик сақланади.

## Мавжуд Render ботига ўрнатиш

1. Ишчи PostgreSQL базасининг захира нусхасини олинг. Янги база яратманг ва мавжуд DATABASE_URL’ни алмаштирманг.
2. ZIP ичидаги `asman-accountingbot-main` папкасининг **ичидаги** файлларни мавжуд GitHub репозиторийга жойланг. `fonts/` ва `tests/` папкалари ҳам керак.
3. Render → Environment’да мавжуд BOT_TOKEN, OPENAI_API_KEY, DATABASE_URL қийматларини сақланг.
4. `ALLOWED_USER_IDS` қўшинг: ўзингизнинг рақамли Telegram ID’ингиз. Бир нечта бўлса вергул билан ёзинг: `123456789,987654321`. Ботга `/start` юборилганда рухсат йўқлиги ҳақидаги хабарда сизнинг ID кўринади. Бу мисол ID’ларни ўзингизникига алмаштиринг.
5. `WEBHOOK_SECRET` учун A–Z, a–z, 0–9, `_`, `-` белгиларидан иборат тасодифий махфий қиймат қўйинг. Токен ва калитларни кодга ёзманг.
6. Start Command: `python start.py`. Build Command: `pip install -r requirements.txt`.
7. Янгиланган кодни deploy қилинг. Ботни `/start` билан очинг.
8. «Топилмаган / хатоли» бўлимида қолган хатоларни кўринг. Акт сверка ва молиявий таҳлилни **янгидан** тайёрланг. Эски сақланган акт тарихий нусха бўлиб қолади.

`render.yaml` янги ўрнатиш учун ҳам бор. Мавжуд базани сақлаш учун оддий код deploy’идан фойдаланинг; Blueprint орқали янги базага ўтиб кетманг.

## Қаторни тузатиш

1. «Топилмаган / хатоли» → тегишли рўйхат → ҳужжат қатори.
2. «Ҳамкорни боғлаш» → СТИР ёки аниқ ном. Агар ҳамкор ҳали йўқ бўлса: `ном | СТИР | ҳисоб рақами`.
3. «Майдонни тузатиш» → мисол: `Сана | 15.09.2026`, `Сумма | 1500000`, `Валюта | USD`.
4. Банк суммаси учун `Кирим | 1500000` ёки `Чиқим | 1500000`; «Сумма» майдони фактурага тегишли.
5. «Тузатишни сақлаш»ни босишдан олдин аввалги ва янги қийматни текширинг.
6. «Фактурага боғлаш» учун қатор ID’си ишлатилади, масалан `d12:r0`. У «Барча ёзувлар»да бор. Ҳамкор, валюта ва йўналиш мос бўлиши шарт.
7. Солиқ/комиссия/ички ўтказма савдо қарзига тегишли бўлмаса, «Савдога тегишли эмас»ни танланг. Пул ҳаракати ҳисоботда сақланади, ҳамкор билан савдо қарзига қўшилмайди.

## Тақсимот усули

- Аниқ фактура рақами ёки қўлдаги боғланиш биринчи ўринда.
- Шартнома аниқ берилган бўлса, шу шартнома ичида аввалги фактурадан бошлаб тақсимланади.
- Рақам/шартнома бўлмаса, бир ҳамкор, йўналиш ва валюта доирасида FIFO қўлланади. PDF буни **тахминий тақсимот** деб белгилайди.
- Қопланмаган фактура ҳақиқий қарз бўлиши мумкин. Тақсимланмаган тўлов эса аванс, етишмаётган фактура ёки бошқа операция бўлиши мумкин. Улар автоматик равишда хато деб эълон қилинмайди.

## Амалий чегаралар

- Реал Telegram/Render/OpenAI калитлари ва ишчи база бу архив билан берилмаган; жонли deploy ва ҳақиқий файллар бўйича солиштириш бажарилмаган.
- Реестрда версия вақти бўлмагани учун версия танлаш **юклаш тартиби**га таянади. Кейинроқ юкланган эски реестр эски ҳолатни қайта жорий қилиши мумкин; энг охирги реестрни охирида юкланг.
- Бошланғич қарз қолдиқларини киритиш интерфейси ҳали йўқ. Акт ва таҳлилда бу аниқ ёзилади; натижа юкланган давр ҳаракатларини кўрсатади.
- Манфий тузатувчи фактуралар ва қайтаришлар учун махсус бухгалтерия проводкалари ҳали йўқ; уларни қўлда текшириш керак.
- Базада йўқ ёки аввалги импортда тушиб қолган операцияни код қайта тиклай олмайди. Манба файлни қайта юклаш керак. Жуда эски фақат preview сақланган выписка учун тўлиқ файл керак.
- Бир хил ҳамкор/шартнома рақамида ҳам харид, ҳам сотув бўлса, шартнома сарфи ноаниқ деб кўрсатилади; икки йўналиш қўшилмайди.
- Омбор ҳаракати журнали, шартнома бўйича товар миқдори ва чиқиш фактураси конструктори ушбу янгиланишда тўлиқ ишлаб чиқилмаган.
- Барча рухсат этилган фойдаланувчиларда бир хил ҳуқуқ бор; роллар алоҳида ажратилмаган.
- Катта базалар учун кейинчалик операцияларни алоҳида индексланган жадвалларга кўчириш мумкин; ҳозир JSON манбалар ўқилади.

## Текшириш

```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```

30 та автоматик синов: шахсларни мослаш, ноаниқ ном ва зид СТИР, версия/бекор қилиш, қисман/кўп тўлов, валюта, дубликат, қўлда тузатиш тарихи, эски тугма, рухсат назорати, текширув менюси ва PDF генерацияси.

PDF намуналарини алоҳида вақтинчалик базада яратиш:

```bash
python demo_reports.py
```
